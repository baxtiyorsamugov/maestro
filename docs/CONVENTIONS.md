# Соглашения по коду

## Кодировка — правило номер один

Проект уже потерял 35 строк интерфейса из-за неверной кодировки (`docs/AUDIT.md`, A-1).

- Все текстовые файлы — **UTF-8 без BOM**, перевод строки `LF`.
- Файлы с кириллицей **не пишутся** через `bash` heredoc, `echo >`, `sed -i` на Windows.
- Русский и узбекский текст пишется **как есть**, не в виде `Зд...`.
  Существующие escape-последовательности — легаси, заменяются при рефакторинге файла.
- Перед коммитом: `grep -rn '???' *.py` должен быть пуст. Это же проверяется в CI.

## Python

- Python 3.11+, форматирование `black` (line-length 100), линт `ruff`, типы `mypy`.
- Аннотации типов обязательны для публичных функций и всех сервисов.
- Именование: `snake_case` для функций и переменных, `PascalCase` для классов,
  `UPPER_SNAKE` для констант.
- Комментарии и docstring'и — на русском, это язык команды. Имена сущностей — на английском.
- Никаких `print()`. Только `logging` / `structlog`.
- Никаких голых `except:` и `except Exception: pass`. Ловим конкретное исключение,
  логируем с контекстом, решаем что показать пользователю.

## Асинхронность и БД

```python
# Правильно: явная подгрузка связей
booking = await session.scalar(
    select(Booking)
    .where(Booking.id == booking_id)
    .options(
        joinedload(Booking.user),
        joinedload(Booking.stylist),
        joinedload(Booking.service).joinedload(Service.catalog_service),
    )
)
```
- Ленивая загрузка в async бросает `MissingGreenlet` — всегда `joinedload` / `selectinload`.
- Сессия открывается на одну логическую операцию и закрывается до сетевых вызовов Telegram.
- Отправка сообщений — **вне** открытой транзакции.
- Схема меняется только миграцией Alembic. Одна миграция = одно осмысленное изменение,
  с работающим `downgrade`.

## Хендлеры aiogram

- Один хендлер = один экран или одно действие. Больше 60 строк — выносим в сервис.
- Каждый callback-хендлер заканчивается `await cb.answer()` (или `cb.answer(text, show_alert=True)`).
- Каждый хендлер, меняющий данные, начинается с проверки прав:
  ```python
  booking = await booking_service.get_for_stylist(booking_id, stylist_id=stylist.id)
  if booking is None:
      await cb.answer("Нет доступа", show_alert=True)
      return
  ```
- Источник истины — база. Никогда не восстанавливаем состояние из `cb.message.text`.
- Состояние шага записи хранится в FSM (`state.update_data`), не в глобальных словарях.

## callback_data

Строковые префиксы через `startswith` запрещены — они пересекаются
(`stylist_` перехватывает `stylist_portfolio_`, `search_` перехватывает `search_district`).

```python
from aiogram.filters.callback_data import CallbackData

class BookingCB(CallbackData, prefix="bk"):
    action: str          # approve | decline | complete | cancel
    booking_id: int

@router.callback_query(BookingCB.filter(F.action == "approve"))
async def approve(cb: CallbackQuery, callback_data: BookingCB): ...
```

Лимит Telegram — 64 байта на `callback_data`. Длинные значения не влезают: храним в FSM,
в callback передаём идентификатор.

## Локализация

- Все пользовательские строки — в `app/locales/{ru,uz}.ftl`. Инлайн-словари
  `{"ru": ..., "uz": ...}[lang]` в хендлерах запрещены.
- Новый текст добавляется **сразу на оба языка**. Нет перевода — не мержим.
- Ключи именуются по смыслу и разделу: `booking.slot_taken`, `stylist.schedule.day_off`,
  `error.access_denied`.
- Числа склоняются через плюрализацию локали, не через `if days == 1`.
- В CI — проверка, что наборы ключей `ru.ftl` и `uz.ftl` совпадают.

## Тексты для пользователя

- Одно сообщение = одна мысль. Максимум 4–5 строк.
- Никаких технических терминов: не «ошибка сессии», а «Время выбора истекло, начните заново».
- Ошибка всегда сообщает, **что делать дальше**, и даёт кнопку для этого.
- Эмодзи — только как маркер статуса (✅ ⏳ ❌ 📅), не для украшения. Не больше двух на сообщение.
- Пользовательские значения в HTML-сообщениях обязательно через `html.escape()`.

## Логирование

```python
logger.warning("booking.notify_failed", extra={"booking_id": b.id, "user_id": u.id, "error": str(e)})
```
- Сообщения-события на английском в формате `домен.событие`, детали — в структурных полях.
- Никогда не логируем `BOT_TOKEN`, пароли, номера телефонов целиком.
- Уровни: `INFO` — бизнес-события (создана запись), `WARNING` — ожидаемые сбои
  (пользователь заблокировал бота), `ERROR` — баги, требующие вмешательства.

## Тесты

- Бизнес-правила покрываются юнит-тестами **обязательно**: расчёт слотов, пересечения,
  подписка, права доступа, окно отмены.
- Тест называется по сценарию: `test_slot_is_unavailable_when_overlaps_approved_booking`.
- Никаких обращений к реальному Telegram API и к боевой базе.

## Git

- Ветки: `feat/<кратко>`, `fix/<кратко>`, `chore/<кратко>`, `docs/<кратко>`.
- Коммиты — Conventional Commits: `fix(bot): восстановить русские строки в сценарии записи`.
- Один коммит = одно изменение. Правка задачи из дорожной карты — вместе с отметкой `[x]`
  в `docs/ROADMAP.md`.
- В `main` — только через PR с зелёным CI.
- В репозиторий не попадают: `.env`, `*.log`, `*.db`, `dist/`, `build/`, `.venv/`, архивы.

## Определение готовности задачи

Задача закрыта, если:
1. код отформатирован, линт и типы проходят;
2. бизнес-логика покрыта тестом;
3. пользовательские тексты есть на ru и uz;
4. `grep -rn '???'` пуст;
5. сценарий вручную прогнан в Telegram;
6. чекбокс в `docs/ROADMAP.md` отмечен.
