# Безопасность Maestro

## 1. Что защищаем

| Актив | Риск при компрометации |
|---|---|
| `BOT_TOKEN` | полный контроль над ботом: чтение переписки, рассылка от имени сервиса |
| Персональные данные клиентов (имя, телефон, `telegram_id`, история визитов) | утечка базы клиентов, репутационный и юридический ущерб |
| Учётная запись админки | изменение тарифов, удаление записей, выгрузка всей базы |
| Целостность записей | подтверждение/отмена чужих броней, накрутка рейтинга |

## 2. Текущие уязвимости

### Критично

**S-1. Нет авторизации в callback-хендлерах** (`bot.py:1516, 1586, 1643, 2651`)
`approve_`, `decline_`, `complete_`, `rate_`, `del_srv_`, `special_*` берут идентификатор
объекта из `callback_data` и не проверяют, имеет ли отправитель к нему отношение.
Любой пользователь Telegram может подтвердить чужую запись, отменить чужой визит,
поставить оценку любому мастеру или удалить чужую услугу.

*Исправление:* фильтр/middleware, сверяющий владельца объекта с `cb.from_user.id`.

**S-2. Пароль админки в открытом виде** (`admin_panel.py:28`)
Хранится в `.env` как есть, сравнивается оператором `==` (не константное время).
Нет ограничения попыток входа, нет журнала входов. `.env.example` предлагает `admin12345`.

*Исправление:* argon2-хеш, `secrets.compare_digest`, лимит попыток, аудит входов.

**S-3. Логи в репозитории**
`admin.log`, `nohup.out` (1.2 МБ), `bot.log` закоммичены в git. Содержат операционные данные.
Даже после удаления остаются в истории.

*Исправление:* `git rm --cached`, при наличии чувствительных данных — перезапись истории
и ротация `BOT_TOKEN`.

### Важно

**S-4. Нет экранирования HTML.** Имя пользователя подставляется в сообщения с
`parse_mode="HTML"` без `html.escape()` (0 вызовов на весь проект). Ломает доставку
сообщений и открывает вставку разметки.

**S-5. Нет антифлуда.** Отсутствует throttling — бот открыт для перебора callback'ов
и для исчерпания пула соединений к БД.

**S-6. Гонка при бронировании.** Между проверкой слота и вставкой нет блокировки и нет
уникального ограничения — двойная бронь достижима намеренно.

**S-7. `.env` рядом с `.exe`.** Windows-сборка требует положить `.env` с боевым токеном
рядом с исполняемым файлом. Любой, у кого есть копия дистрибутива, получает токен
и доступ к базе. Раздавать `.exe` с боевым `.env` нельзя.

**S-8. Нет модели удаления данных.** Пользователь не может удалить свой аккаунт и историю.

## 3. Правила для разработки

- Секреты — только в `.env`, никогда в коде, коммитах, логах и сообщениях об ошибках.
- `.env.example` содержит **плейсхолдеры**, а не рабочие значения.
- `ADMIN_SECRET_KEY` — не меньше 32 случайных байт, свой для каждого окружения.
- Каждый хендлер, меняющий данные, начинается с проверки прав. Без исключений.
- Идентификаторы из `callback_data` — **недоверенный ввод**. Всегда сверяем с владельцем.
- Пользовательский ввод не попадает в HTML-сообщения без `html.escape()`.
- В логи не пишем токены, пароли и полные номера телефонов.
- Админка не выставляется в интернет без HTTPS и обратного прокси.
- Зависимости обновляются регулярно; в CI — `pip-audit`.

## 4. Чек-лист перед выходом в прод

- [ ] `BOT_TOKEN` не встречается ни в одном коммите за всю историю
- [ ] Логи, `.db`, `.env`, архивы удалены из индекса git
- [ ] Пароль админки захеширован, дефолтные учётные данные заменены
- [ ] Ограничение попыток входа в админку включено
- [ ] Все callback-хендлеры проверяют права (S-1 закрыт)
- [ ] Throttling-middleware включён
- [ ] Уникальное ограничение на слот в БД создано
- [ ] Админка только по HTTPS, доступ ограничен по IP или VPN
- [ ] Бэкапы базы настроены и **восстановление проверено на копии**
- [ ] Sentry подключён, в события не попадают персональные данные
- [ ] Опубликована политика обработки данных, в боте есть `/privacy`
- [ ] Реализовано удаление аккаунта и данных по запросу пользователя

## 5. Если токен утёк

1. @BotFather → `/revoke` → получить новый токен.
2. Обновить `.env` на всех окружениях, перезапустить бота.
3. Проверить логи Telegram на посторонние рассылки.
4. Удалить старый токен из истории git (`git filter-repo`), уведомить всех, у кого есть клоны.
5. Сменить `ADMIN_SECRET_KEY` и пароль админки — сессии станут недействительны.
